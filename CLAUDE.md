# Origin-Weapon — правила для работы над проектом

Paper 1.21.10, Java 21, Gradle (Kotlin DSL). Пакет: `dev.yukio.originweapon`.
Общаемся и пишем комментарии/сообщения в конфиге на русском.

## Как устроен проект

- Пользователь присылает идеи предметов — на **каждый предмет отдельный класс**
  в `src/main/java/dev/yukio/originweapon/item/` (при необходимости подпакет по расе),
  реализующий `OriginItem`.
- Каждый предмет имеет уникальный `id()`; это ключ секции `items.<id>` в `config.yml`.
- Предмет помечается через PDC (ключ `originweapon:item_id`), не по имени/лору.
- Все механики предмета проверяют `items.<id>.enabled` — выключенный предмет
  не срабатывает вообще (и не выдаётся командой).
- Все числа (урон, радиус, кулдаун, длительность эффектов), имя и лор берутся из
  конфига, а не хардкодятся. Тексты — MiniMessage.

## config.yml — обязательное правило

При добавлении нового предмета **всегда** добавлять его секцию в
`src/main/resources/config.yml` со всеми параметрами и комментариями.
На сервере конфиг должен дополняться автоматически: недостающие ключи из
дефолтного конфига дописываются в существующий файл, пользовательские значения
не перезаписываются (поднимать `config-version` при изменении структуры).

## Что ещё не сделано (каркас)

- `ItemRegistry` — регистрация предметов и их слушателей
- обновление/мерж `config.yml`
- команды `/originweapon give <id> [player]` и `/originweapon reload` (Brigadier)
- таблица предметов в README — обновлять при добавлении каждого предмета

## Сборка

Gradle wrapper не закоммичен: локально `gradle build` (или сгенерировать wrapper
командой `gradle wrapper`). CI — `.github/workflows/build.yml`.
